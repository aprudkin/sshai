# Security policy

## Supported versions

Security fixes are made on the current `main` branch until a versioned release policy is published.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, credential exposure, or unsafe remote-execution path. Use GitHub private vulnerability reporting for this repository when available. Otherwise contact the repository owner through the GitHub profile with a minimal reproduction using synthetic values.

Do not send passwords, tokens, private keys, host inventories, captured artifacts, or customer data. Include the affected revision, impact, reproduction steps, and suggested mitigation. `sshai` does not remove the need to authorize remote actions independently.
