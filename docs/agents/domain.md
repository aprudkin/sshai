# Domain documentation

Use a single context for sshai: `GLOSSARY.md` at the repository root and
architecture decision records under `docs/adr/`.

Before exploring a domain concept, read the glossary if present and relevant
ADRs if present. Until definitions are recorded there, consult the module
boundaries in [AGENTS.md](../../AGENTS.md) and the applicable implementation
and usage contracts.

Use the `domain-modeling` skill when defining terms or recording an architectural
decision. Surface contradictions before changing established terminology.
Create glossary entries and ADRs only for concrete agreed terms or decisions;
this layout does not require empty placeholder files.
