# sshai fan-out benchmark protocol v2.1 amendment 1

**Task:** [aimem#743](https://github.com/aprudkin/aimem/issues/743)

**Protocol version:** 2.1-amendment-1

**Status:** frozen before the first amended measured run

This amendment governs only a new artifact root and manifest. The completed historical v2.1
measurement ending in `decision=inconclusive` remains governed by the source and manifest frozen
for that measurement; this amendment does not reanalyze, append to, or reinterpret it.
Branch prompts, command markers, no-op envelopes, run metadata, and branch-validation schemas stay
at v2.1 because their within-branch contract is unchanged; the amendment versions only the
study-level manifest, schedule, analysis, and decision rule.

This protocol supersedes the experimental design in
[v1.1-protocol.md](v1.1-protocol.md). It does not replace or reinterpret the historical v1.1
result.

## Decision this benchmark must support

Determine whether `sshai` fan-out reduces agent-visible command calls and control-adjusted Codex
input cost without losing per-host evidence or lowering the observation success rate. The result
may be `confirmed`, `needs-work`, `inconclusive`, or `invalid`; a single run cannot support a
reliability claim.

## Experimental unit

One replicate is two adjacent, independently fresh pairs whose internal and pair ordering is
frozen by the interleaving schedule below:

1. one `raw-control`/`raw` pair;
2. one `fanout-control`/`fanout` pair.

Run eight complete replicates. Each branch is one fresh `codex exec --json` session containing one
user turn and one final response. Model, reasoning effort, instructions, working tree, scenario,
target order, and 180-second per-call watchdog are identical within the four branches. The control
for each workload branch has the same prompt structure, marked-call count, marker layout, and
bounded result shape as its pair, but executes a deterministic local no-op helper and no remote
payload.

Every branch starts with a separate fresh `CODEX_HOME` under one frozen root. Its initial allowlist
contains only a link to the same private authentication source; it contains no global instructions,
skills, plugins, configuration, cache, or prior session. `--ignore-user-config` remains mandatory.
Runtime-created state stays inside that branch home and is never reused by another branch. This
prevents environment-owned setup calls and warm state from entering only some populations.
The runtime may read the model-visible `sshai` skill once before executing marked calls. Its exact
file digest is frozen; only a successful `cat` or bounded `sed` read whose output digest matches
that file is accepted as unmarked local setup. It remains outside every marked metric population.

The two controls are deliberately separate. A 36-call control cannot represent the fixed cost of
a 24-call fan-out branch, and a common control would confound call-count savings with remote
payload savings.

## Frozen sampling and interleaving

The manifest freezes eight replicates as two repetitions of this exact balanced four-replicate
cycle:

| Replicate in cycle | Exact branch order |
|---:|---|
| 1 | `raw-control`, `raw`, `fanout-control`, `fanout` |
| 2 | `raw`, `raw-control`, `fanout`, `fanout-control` |
| 3 | `fanout-control`, `fanout`, `raw-control`, `raw` |
| 4 | `fanout`, `fanout-control`, `raw`, `raw-control` |

Each workload remains adjacent to its own control. Across one cycle, raw and fan-out pairs each
appear first twice, and workload-first/control-first ordering is balanced. Repeating the complete
cycle gives eight predeclared samples without choosing a favorable order after observing usage.
Every run metadata document publishes its complete replicate row and zero-based branch index; the
analyzer requires both to match the manifest.
There is no early success stop, replacement replicate, or optional extension. A failed frozen
contract invalidates the study root; preserve it and restart the complete eight-replicate study in
a new root. A valid control-floor result remains in the fixed sample and is not rerun.

## Declared call and observation populations

The manifest freezes 36 observation IDs: 12 ordered read-only observation classes on each of two
Linux/bash aliases and one Windows/PowerShell 7 alias.

| Branch | Marked command calls | Observations represented | Remote payload |
|---|---:|---:|---|
| `raw-control` | 36 | 36 synthetic control observations | none |
| `raw` | 36 | 36, one host per call | direct SSH |
| `fanout-control` | 24 | 36 synthetic control observations | none |
| `fanout` | 24 | 36: two Linux hosts in one fan-out call plus one Windows call per class | `sshai` |

Every planned command carries exactly one `BENCH_V21_CALL` marker and one `BENCH_V21_OBS` marker
as environment assignments immediately prefixed to its executable invocation. The invocation-bound
form prevents shell comment elision from removing call identity. The Linux fan-out call declares
two observation IDs; every other planned call declares one. The analyzer rejects missing,
duplicate, malformed, unexpected, or multiply assigned markers instead of reconstructing intent
from command prose.

Unmarked setup or diagnostic calls are published separately. They never enter marked-call p95,
sum, retry, call-reduction, success, or acceptance calculations. An unplanned remote call makes
the replicate invalid; a bounded local diagnostic may be retained as unmarked evidence but cannot
repair a failed acceptance population.

## Branch mechanics

### Raw pair

The `raw` branch uses direct SSH exactly once for every host/observation combination. Linux bodies
travel to `bash -s`; the Windows body travels to PowerShell 7 over stdin. Before the first branch,
the runner materializes all 36 manifest bodies as immutable local input files and verifies their
exact inventory and bytes before every later branch and analysis. Prompts reference those files
with one-line commands instead of asking the model to reproduce body bytes. No output filtering,
redirection, or artifact substitution is allowed before stdout/stderr reaches the Codex command
tool. The local watchdog terminates each SSH process after 180 seconds without filtering output.

`raw-control` replaces each remote invocation with the frozen local no-op helper. It retains the
same 36 call and observation markers, expected exits, ordering, and bounded control envelope.

### Fan-out pair

For each observation class, `fanout` issues one Linux call with both Linux aliases in argv order
and one Windows call. It uses
`sshai run --body-file <manifest-input> --timeout 180 --result-format=json`, where
`<manifest-input>` is the verified absolute body-file path for that observation. Repeated
diagnostic observations retain their frozen `--ctx` and `--delta` behavior. The machine-readable
envelope must contain one result for every declared host in argv order, including host, remote
exit, artifact identity, and outcome. Shell exit alone is not per-host evidence.

`fanout-control` replaces those 24 invocations with the frozen local no-op helper. Each Linux
control envelope represents the same two declared observations, and each Windows envelope the
same one observation. It performs no SSH, target lookup, artifact read, or remote payload.

## Runtime and executable preflight

Before freezing an amended measured manifest:

1. require a clean checkout with local `HEAD` equal to its upstream;
2. run the focused analyzer tests, `go test ./...`, `go test -race ./internal/cli`, `go vet ./...`,
   and `go build ./...`;
3. resolve `sshai` from `PATH`, record its absolute path and SHA-256, and require Go build metadata
   `vcs.modified=false` with `vcs.revision` equal to the intended source revision;
4. smoke-test that exact binary through a no-SSH CLI path;
5. freeze one exact bounded, read-only probe command, command digest, expected exit, output byte
   limit, and expected OS/shell output lines for each target; qualification evidence must retain
   the captured output bytes and bind their absolute path, size, digest, and parsed lines to the
   matching target and frozen command;
6. freeze the Codex version, model, reasoning effort, prompt and helper digests, target facts,
   command bodies, expected exits, the exact eight-row branch schedule, decision rule, timeout,
   analyzer revision, and a new empty artifact directory.

The executable path is descriptive identity, not sufficient provenance. Revision, digest, build
modified state, and smoke result must all agree.

## Analyzer and lifecycle definition

The normative metric populations, lifecycle types, validation rules, and equations are in
[v2.1-analyzer.md](v2.1-analyzer.md). That definition and its negative-control tests are frozen
before measurement.

Codex-exec and persisted-rollout compactions are counted only from exact schema-defined lifecycle
record types. Words such as `compact`, `compaction`, or `truncated` inside commands, output,
reasoning, or messages are not lifecycle events. The two sources must identify the same thread and
same compaction count; otherwise the replicate is invalid.

## Metrics and decision rule

Publish, without silent subtraction:

- total, cached, and non-cached input tokens for all four branches in every replicate;
- marked and unmarked command-call counts and marked tool-output sum/p95/max;
- declared-observation coverage, per-host outcomes, retries, and compactions;
- raw call reduction from 36 to 24;
- `raw - raw-control` and `fanout - fanout-control` input-token marginals;
- the fan-out reduction relative to a positive raw marginal.

A non-positive workload marginal is reported as `indistinguishable-from-control-floor`; it is not
zero usage and cannot produce a percentage reduction. The pair remains in the fixed sample but
does not contribute a numeric reduction.

`confirmed` requires all eight replicates to be valid and all of the following on their declared
populations:

- 36 raw and 24 fan-out marked calls, a 33.33% call reduction;
- all 36 observations present in both workload branches;
- fan-out success rate at least raw success rate within every replicate;
- fan-out marked-call p95 below 500 estimated tokens;
- zero compactions in both sources;
- at least six of eight input-token pairs with both workload marginals positive and therefore a
  defined control-adjusted reduction;
- no more than two input-token pairs labelled `indistinguishable-from-control-floor`;
- median control-adjusted input-token reduction of at least 80% across the defined pairs.

If fewer than six reductions are defined, or more than two pairs are at the control floor, the
fixed eight-replicate measurement is `inconclusive` regardless of the median of the remaining
pairs. With sufficient defined pairs, a valid complete measurement that misses the 80% median or
another acceptance target is `needs-work`. Any frozen-contract violation is `invalid` and
produces no comparative decision.

## Invalidation and restart

Invalidate the entire study root and restart all eight replicates in a new artifact root if any
frozen prompt, command body, helper, target, model, reasoning effort, executable revision/digest,
analyzer definition, lifecycle schema, timeout policy, branch schedule, decision rule, or artifact
path changes after its first branch starts. Never append a corrected branch or replacement
replicate to the old root.

Retain invalid and pilot evidence with its reason. Do not mix its tokens, calls, or observations
into a valid replicate.

## Safety boundary

The remote scenario is read-only and limited to the three frozen aliases. It must not enumerate
environment variables, histories, credentials, configuration bodies, sensitive logs, process
arguments, or network endpoints. Normal SSH/session activity and `sshai`'s temporary PowerShell
staging file are the only allowed target-side effects. The no-op controls must not open network
connections.
