# sshai v1.1 benchmark protocol

**Task:** [aimem#735](https://github.com/aprudkin/aimem/issues/735)

**Protocol version:** 2

**Version 1 frozen before target qualification:** 2026-08-12

**Version 2 amendment:** 2026-08-13, before any valid measured pair

Version 1 produced only an aborted raw-SSH pilot. Its second 10 MB Linux stream (`L22`) remained
active for more than 15 minutes, so the branch was stopped before Windows and before any measured
`sshai` branch. The pilot is retained outside the repository and is not used in comparative
metrics. Version 2 changes only the controls needed to make the experiment terminal:

- retain one approximately 10 MB producer on the first Linux host;
- use approximately 1 MB producers on the second Linux and Windows hosts;
- apply an explicit 180-second watchdog to every remote call in both branches.

Both measured branches restart in a new artifact directory. No v1 pilot tokens or steps are mixed
into the v2 result.

## Decision this benchmark must support

Compare `sshai` with direct raw SSH in fresh Codex sessions and decide whether v1.1 demonstrates
lower agent-context cost without a lower observation success rate. The benchmark may conclude
"confirmed", "needs work", or "inconclusive". A target missed because both branches hit a Codex
tool-output floor is inconclusive, not a literal zero cost or a saving above 100%.

## Fixed controls

- Codex CLI: the installed version recorded in the run manifest.
- Model and reasoning effort: identical in both branches, explicitly pinned in the manifest.
- Branch order: raw SSH first, then `sshai`. Duration is descriptive, not a pass/fail metric, so
  connection warming cannot decide the result.
- Sessions: fresh non-ephemeral `codex exec --json` sessions. They use the same global/project
  instructions and the same working tree. No session is resumed.
- Targets: exactly two Linux/bash aliases and one Windows/PowerShell 7 alias from `ssh_config`.
  Qualification is a separate, read-only preflight. The selected aliases and observed OS are
  frozen in a committed manifest before either measured branch runs.
- Mutations: none on the targets except normal SSH/session activity and `sshai`'s temporary remote
  staging file. Synthetic output is generated in memory and is not written remotely.
- Secrets: commands must not enumerate environment variables, command history, account data,
  configuration bodies, logs, process arguments, or network endpoints.

## Scenario

Each target receives the same 12 observation classes, for 36 required steps per branch:

1. OS/kernel identity;
2. uptime;
3. logical CPU count;
4. bounded memory summary;
5. root/system-drive capacity summary;
6. process count, without names or arguments;
7. TCP connection count, without endpoints;
8. deterministic 2,000-line synthetic diagnostic output;
9. identical repeat of step 8 (`--delta` in the `sshai` branch);
10. deterministic line-oriented synthetic output: approximately 10 MB on the first Linux target
    and approximately 1 MB on the second Linux and Windows targets;
11. intentional read-only exit code 7;
12. a small successful health probe after the failure.

The manifest contains the exact Linux and PowerShell bodies. A step succeeds when the tool call
finishes, the observed exit matches the expected exit, and output needed to recognize the
observation is present. Step 10 need not be fully visible to Codex; the point is to measure the
agent-visible response while confirming that the producer emitted the intended line count. In the
`sshai` branch the complete artifact line count is evidence. In raw SSH, an upstream harness
truncation marker or a response plateau is recorded as a coverage boundary.

## Branch mechanics

### `sshai`

- One agent shell call per step.
- Every body is passed with `sshai run --body-file - <alias>`.
- Steps 8 and 9 share an isolated `--ctx`; step 9 adds `--delta`.
- The agent reads passports and may use `sshai q` only when the step's success cannot otherwise be
  established. Such a query is an additional planned evidence call, not a remote rerun.
- The full remote body must not be printed from the local artifact into the conversation.

### Raw SSH baseline

- One agent shell call per step initially.
- Linux bodies use direct `ssh <alias> bash -s`; Windows bodies use direct SSH into PowerShell 7
  with the body on stdin.
- No `head`, `tail`, `grep`, redirection, or other output reduction is allowed before the Codex
  shell tool receives stdout/stderr.
- A local watchdog terminates a single raw SSH process after 180 seconds; it forwards stdin and
  stdout unchanged and performs no output filtering.
- A failed syntax/transport call may be retried at most twice. Extra calls are counted as
  quoting-debug turns. Unsupported or still-failing steps remain failures.

Every required call carries a `BENCH_STEP=<id>` marker in its shell command so the analyzer can
distinguish retries, omissions, and unplanned calls without trusting the final prose.

## Metrics

| Metric | Source | Calculation |
|---|---|---|
| Input-token reduction | final `turn.completed.usage.input_tokens` | `(raw - sshai) / raw` |
| Cached and non-cached input | the same usage object | report both; do not subtract a control floor silently |
| Tool-response p95 | completed `command_execution.aggregated_output` | nearest-rank p95 of `ceil(UTF-8 bytes / 4)` |
| Compactions | Codex JSONL events and persisted rollout | count explicit compaction events; cross-check the rollout |
| Success rate | observed command exits plus required evidence | successful required steps / 36 |
| Quoting-debug turns | marker-grouped command executions | calls beyond the first attempt, excluding declared `sshai q` evidence calls |
| Duration | wall clock and command events | descriptive only |

The bytes/4 conversion is an estimate, not a model tokenizer. Actual Codex input usage is the
primary token metric. Agent messages are retained in the JSONL but are not tool responses.

## Preflight and invalidation

Before measurement:

1. the repository is clean and local `HEAD` equals its upstream;
2. `go test ./...` and `go vet ./...` pass;
3. each alias is reachable through `sshai`, reports the required OS/shell, and passes a tiny
   read-only command;
4. the manifest freezes aliases, command bodies, model, reasoning effort, Codex version, sshai
   Git SHA, branch order, and artifact directory;
5. no benchmark JSONL already exists at the selected artifact paths;
6. every generated branch command contains the frozen 180-second watchdog.

Invalidate both branches and restart with a new versioned manifest if a command body, target,
model, reasoning effort, output size, branch prompt, or analyzer definition changes after the
first measured branch starts. A host outage after freezing is a measured failure unless independent
evidence shows an external outage; do not silently substitute another target.

## Decision rule

The v1.1 claim is **confirmed** only if all are true:

- input-token reduction is at least 80%;
- `sshai` p95 agent-visible tool response is below 500 estimated tokens for this scenario,
  including the approximately 10 MB producers;
- the `sshai` session has zero observed compactions;
- `sshai` success rate is at least the raw baseline success rate;
- `sshai` has approximately zero quoting-debug turns (operationalized here as at most one).

If measurement coverage is incomplete, report the individual observations and conclude
"inconclusive" rather than promoting targets to results.
